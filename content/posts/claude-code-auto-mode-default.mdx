On August 14, Anthropic will switch Claude Code’s auto mode from an opt‑in feature to the default for Pro, Max, and Team plans. Auto mode lets the assistant run tool calls without prompting the user, only intervening when a classifier flags an irreversible, destructive, or out‑of‑environment action. The change also removes the per‑call classifier fee for these plans. Anthropic says internal testing and a study of 1,053 paid testers showed auto mode blocks 89 % of harmful actions, far outperforming manual approval. For developers, this promises faster, less‑interruptive workflows while raising new safety considerations.

<Callout type="takeaway">Auto mode becomes the default for Claude Code Pro, Max, and Team plans, delivering faster autonomous coding with higher measured safety.</Callout>

## What happened
Starting August 14, new Claude Code sessions on Pro, Max, and Team subscriptions will run in auto mode by default. Users who have set a different default will see a one‑time prompt to switch, while pinned defaults remain unchanged. The auto‑mode classifier adds only a few extra tokens per tool call and Anthropic has stopped charging for that overhead on these plans.

Auto mode stays opt‑in for Enterprise, the Claude API, and cloud‑hosted versions, giving admins time to review the change. Enterprise admins can still make auto mode the default through managed settings. The classifier blocks actions deemed irreversible, destructive, or targeting resources outside the defined environment, and falls back to manual approval after three consecutive blocks or twenty blocks in a session.

Anthropic evaluated safety through internal red‑team exercises, third‑party red‑team testing, and a controlled study with 1,053 paid testers. Across all measures, auto mode matched or outperformed manual review, blocking 89 % of injected harmful commands compared with only 13.6 % blocked by humans.

## Why it matters
Auto mode removes the constant prompt fatigue that slows down developers, allowing longer autonomous runs such as Claude Opus 5 to execute for hours on large codebases. By catching the majority of risky actions automatically, teams can ship features faster while maintaining a higher safety baseline than manual approvals, which historically let through 86 % of harmful prompts. The removal of classifier‑related charges also reduces operational costs for Pro, Max, and Team users. However, the 11 % of dangerous actions that still slip through mean organizations must retain monitoring and fallback mechanisms, especially in production environments.

## How to think about it
Treat auto mode as the new baseline, not a set‑and‑forget feature. Enable it for all new sessions, but keep a manual‑approval fallback for high‑risk workflows such as database migrations or production deployments. Review the classifier logs regularly and adjust the auto‑mode configuration (trusted repos, environment context, hard‑deny rules) to match your organization’s security posture. For teams on Enterprise plans, use the managed settings to enforce auto mode where appropriate while retaining the ability to override defaults for sensitive projects.

<Callout type="warning">Auto mode still misses roughly 11 % of harmful actions, so you should monitor classifier decisions and be prepared to intervene manually for critical operations.</Callout>
