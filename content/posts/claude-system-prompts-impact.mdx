Claude’s web interface and mobile apps now prepend every conversation with a system prompt that injects live context, such as the current date, and enforces stylistic rules like always returning code in Markdown. This behavior is part of a periodic update cycle that Anthropic rolls out to improve response quality. However, the same system prompt is not applied when developers call the Claude API, creating a divergence between UI and programmatic usage. For builders who rely on consistent output, understanding this split is essential. The change also marks the transition to fixed‑snapshot model IDs starting with Claude 4.6.

<Callout type="takeaway">Claude’s UI system prompts add live context and formatting rules, but the API remains untouched, so developers must manage prompts themselves.</Callout>

## What happened
Claude’s web UI and mobile clients now automatically prepend a system prompt to every new conversation. The prompt supplies up‑to‑date information—most notably the current date—and instructs the model to always format code snippets in Markdown, ensuring a uniform developer experience across the interface.

Anthropic updates this system prompt on a regular cadence to refine behavior, but those updates are confined to the UI and mobile apps. The Claude API does not inherit these changes; API callers receive only the model’s base capabilities unless they supply their own system prompt. Additionally, starting with the Claude 4.6 generation, each model identifier represents a single, immutable snapshot, eliminating version drift within that model family.

## Why it matters
The built‑in system prompt removes friction for end users who expect fresh context and clean code formatting, which can accelerate prototyping and debugging. Conversely, API consumers must recreate that context manually, adding overhead to integration pipelines and increasing the risk of inconsistent outputs between UI testing and production code. Fixed‑snapshot model IDs also give developers confidence that a given model version will not change unexpectedly, but they must be aware that the system prompt layer is separate from the model itself.

## How to think about it
Treat the UI system prompt as a convenience layer rather than a core feature of Claude. When building with the API, explicitly prepend a system prompt that mirrors the UI’s behavior: include the current date, request Markdown‑formatted code, and any other stylistic preferences. Pin your code to a specific Claude 4.6 snapshot to guarantee model stability, and version‑control your custom prompt alongside your application code. Test both UI and API paths side‑by‑side to catch any divergence early.

<Callout type="warning">Do not assume the Claude API will supply the current date or enforce Markdown; you must add those instructions yourself.</Callout>
