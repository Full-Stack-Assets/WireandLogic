Last week a developer launched a web utility called Dark Hours that shows the night sky. The app was built with Claude, an AI code generator, and within hours the creator realized it was almost identical to an existing open‑source project of the same name. After the similarity was pointed out, the developer redirected the domain, halted further development, and posted a public apology. This incident highlights the hidden risks of relying on AI to generate production‑ready code without proper review.

<Callout type="takeaway">AI can unintentionally reproduce existing open‑source code, so developers must verify originality before release.</Callout>

## What happened
The author announced the launch of Dark Hours, a website that predicts what will be visible in the night sky. The project was generated primarily with Claude, and the resulting code included the same feature set, UI layout, and even a bug that had been fixed in the original open‑source repository.

After a fellow developer highlighted the overlap on Bluesky, the author examined the code and confirmed the duplication. He redirected the darkhours.app domain to the original project, cancelled plans for an iOS version, and issued a blog post acknowledging the mistake.

The incident was discussed on Hacker News, where additional context about a prior astrology‑app rejection and broader concerns about AI‑generated content were raised, underscoring the community’s unease with unchecked AI output.

## Why it matters
Copying an open‑source project without attribution can violate licenses, erode trust, and damage the collaborative ecosystem that powers much of modern software. When AI tools reproduce existing code, the responsibility falls on the human operator to detect and remediate the issue, otherwise legal and reputational risks arise. Moreover, such incidents fuel skepticism about AI’s role in development, potentially prompting stricter policies from platforms and employers.

## How to think about it
Treat AI as a co‑pilot, not an autonomous author. Before committing AI‑generated files, run a similarity scan against known repositories, verify license compatibility, and perform a manual code review. Keep a clear provenance log of prompts and model outputs so you can trace decisions. If the generated code forms a substantial portion of a product, consider rewriting or heavily refactoring to ensure originality.

<Callout type="warning">Do not ship AI‑generated applications without a thorough audit for plagiarism, licensing conflicts, and hidden bugs.</Callout>
