OpenAI just released a preview of its long‑awaited ChatGPT desktop application for Linux. The app bundles the core ChatGPT chat, the new ChatGPT Work workspace, and the Codex code‑assistant into a single Electron‑based client. It ships as native .deb and .rpm packages for Ubuntu, Debian, Fedora and also supports ARM64, with community‑maintained builds offering AppImage and pacman variants. While the launch brings a first‑class Linux experience, several key features from the macOS/Windows versions are still missing. For developers and power users, the availability—and the gaps—shape how they can integrate AI into their local workflows.

<Callout type="takeaway">The Linux preview delivers core ChatGPT and Codex functionality but lacks native computer‑use features.</Callout>

## What happened
On Tuesday OpenAI announced the preview, stating Linux was “one of the most‑requested platforms” and listing supported distributions (Ubuntu 24.04/26.04 LTS, Debian 13, Fedora 43/44) and architectures (x64, arm64). The official package reuses the same Electron runtime and bundled resources as the macOS app, with the .deb signed by OpenAI; community projects such as ilysenko/codex-desktop-linux verify the upstream payload and repack it for additional formats (rpm, pacman, AppImage, Nix).

Early adopters reported functional parity for ChatGPT and Codex, but noted that Linux cannot yet perform “computer use” – the ability for the model to control external desktop applications – and some users experienced Japanese IME issues on Fedora KDE.

## Why it matters
For developers, having a native client means lower latency, offline token storage, and tighter integration with local tooling such as editors and terminals. The inclusion of Codex opens the door to on‑device code generation workflows without switching browsers. However, the missing computer‑use capability limits automation scenarios that rely on AI‑driven UI interactions, a feature that powers many enterprise use‑cases on macOS and Windows. Additionally, preview‑stage software can introduce breaking changes, so teams must plan for version churn.

## How to think about it
Evaluate whether your workflow relies on core chat and code assistance only; if so, the Linux preview is ready for production use. If you need AI‑driven desktop automation, keep a fallback to the web version or wait for a future update. Leverage the community‑maintained packages when you run a distro without official .deb/.rpm support, but verify the upstream signature before installing. Test your input method configuration early, especially on Wayland, and consider running the app under XWayland if IME issues arise. Finally, monitor OpenAI’s release notes for the upcoming computer‑use feature roadmap.

<Callout type="warning">Do not assume the Linux client offers the same desktop‑automation capabilities as the macOS/Windows versions; using it for tasks that require native computer‑use will fail until the feature is added.</Callout>
